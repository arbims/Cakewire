Morph DOM

Après chaque réponse AJAX et lors de wire:navigate, CakeWire met à jour le DOM avec morphdom au lieu d’un remplacement brutal via innerHTML.

Pourquoi

  • Seuls les nœuds modifiés sont touchés.
  • Meilleure préservation du focus et moins de clignotement dans les listes.
  • Comportement plus proche de Livewire 3 qu’un remplacement HTML complet.

Comportement

  • Le nœud x-data="cakewireShell()" (wrapper) reste ; seuls ses enfants sont morphés.
  • wire:key="…" → data-cakewire-key (PHP et JS) pour réconcilier les listes.
  • wire:ignore (x-ignore) : le sous-arbre n’est pas mis à jour.
  • L’élément focus (input, textarea, select) n’est pas écrasé pendant la frappe.
  • Les inputs type="file" ne sont pas remplacés (limitation navigateur).

Chargement

CakeWireHelper::runtimeScripts() charge dans l’ordre :

  1. /cake_wire/js/morphdom.min.js
  2. /cake_wire/js/cake-wire.js
  3. Alpine.js (CDN)

Fallback

Si window.morphdom est absent, CakeWire retombe sur innerHTML.

API debug

CakeWire.morphComponentDom(rootElement, htmlStringFromServer);

Bonnes pratiques

  • Ajoutez wire:key sur chaque ligne de liste (wire:key="user-").
  • Enveloppez du JS tiers ou des widgets dans wire:ignore.
  • Pour des UI très dynamiques Alpine, un wire:ignore ciblé peut être nécessaire (pas d’équivalent complet à @alpinejs/morph).
