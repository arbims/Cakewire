Cycle de vie

Étapes serveur + client

  1. Montage PHP — ComponentRegistry instancie la classe ; mount($properties) hydrate les propriétés publiques passées au helper.
  2. Premier rendu — renderHtml() : vue PHP, compilation WireDirectiveCompiler, HTML injecté dans le wrapper du helper.
  3. Init Alpine — cakewireShell() + init() ; bindWire pour poll, init, dirty, etc.
  4. Interaction — clic, submit, wire:model, poll → POST /cake-wire/update.
  5. Traitement PHP — hydrate($state), uploads, action autorisée, sync live, renderHtml().
  6. Patch DOM — morphdom sur les enfants du wrapper ; bindWire ; Alpine.initTree() ; restauration du focus si besoin.

Payload de requête (action)

{
  "component": "counter",
  "state": { "count": 1 },
  "action": "increment",
  "params": []
}

Payload (sync / wire:model.live)

{
  "component": "contact-form",
  "state": { "email": "user@example.com", ... },
  "syncProperty": "email"
}

Sans action : synchronisation + re-rendu uniquement. Avec $validationRules, le serveur exécute validateOnly() et le hook updated{Property}() (ex. updatedEmail()).

Réponse JSON

{
  "html": "<div>...</div>",
  "state": { "count": 2 }
}

Les erreurs de validation sont dans state._errors (non hydratées depuis le client).
