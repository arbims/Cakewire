Sécurité

Whitelist d’actions

Seules les méthodes listées dans protected array $actions peuvent être invoquées via wire:click, wire:submit, wire:on:*, etc. Toute autre action renvoie une erreur 400.

Enregistrement des composants

L’alias du payload (component) doit correspondre à une entrée Configure::write('CakeWire.components.*'). Ne exposez que les classes destinées à être montées côté client.

État client non fiable

state JSON peut être modifié dans les DevTools. Ne jamais se fier au client pour :

  • authentification ou autorisation ;
  • ownership d’enregistrements ;
  • validation métier critique.

Re-validez toujours en PHP (session, policies, requêtes ORM).

CSRF

Le runtime envoie X-CSRF-Token (meta csrfToken dans le layout via headAssets()). Sans token valide : réponse 403.

Propriétés hydratées

  • Seules les propriétés publiques non statiques sont hydratées depuis le client.
  • Les propriétés readonly sont ignorées à l’hydratation.
  • state._errors n’est jamais appliqué depuis le client (hydrate unset).

Uploads

Seuls les champs déclarés dans $uploads sont acceptés. Fichiers stockés sous tmp/cakewire_uploads/ — configurez une stratégie de production (validation MIME, taille, stockage sécurisé).
